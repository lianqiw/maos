Your earlier fixes in 88beaf2da that were incomplete

  • lib/mkh.c:
    • Only the cubic loop (~289) was fixed, and it never ran, because wtsum is never accumulated there. The fix adds wtsum+=weight.

Decisions (option applied unless noted)

  1. lib/mkh.c bilinear renormalization.
    • (a) Applied: match prop(), with edge renormalization plus alpha.
    • (b) Apply alpha only.
    • (c) Delete the dead block and document that mkh does not renormalize.
    • The cubic wtsum+=weight goes with this choice.
  2. math X(add) with ac==0. The fix makes it scale B by bc, as documented. The alternative is to keep the old no-op and fix servo.c:832 locally instead.
  3. math X(spcell2sp). The fix no longer modifies the const input, and the output is unchanged. The side effect is that muv's A->M keeps its dense block.
  4. math X(minsearch): zero components give a degenerate simplex. Not patched, because the step size depends on the caller.
  5. lib/mkw.c mkw_annular: the normalization cancellation is inexact. Not patched; fixing it would change annular fitting weights.
  6. lib/accphi.c prop_nongrid_rot with cubic: rotation is ignored. The fix only adds a warning; rotation could be implemented instead.
  7. skyc/aster.c multirate: the fix tests SNR at the rate actually assigned (idtrat_fast2). The alternative is to keep the stricter idtrat_fast test.
  8. skyc/genstars.c index: the fix clamps it, so results are bit-identical except for draws that were out of bounds. A uniform floor() draw would change every star field.
  9. maos/powfs.c wfspupmask: unused, and its radius formula always gives d/2. Remove or fix it; not patched.
  10. Behavior choices in tools:
    • ethtest_standalone.c: the F_SETFD line is a no-op. Not patched; recommend deleting it.
    • GTK4 scroll-zoom: the fix also flips the direction to match GTK3. Drop that part if the GTK4 direction was intended.

**#20/#21 mkh renormalization (high impact).** Since 2014 (78d14e894), the bilinear mkht renormalization loop has scaled bx[count], an unused slot, so it had no effect. The fix changes HXW, HA, HXF, the NCPA HA, the pywfs si, and the mkdtf si at edge points where some interpolation neighbors are missing: they get renormalized to sum to alpha, the same as prop(). Options:

  • (a) Keep the fix (recommended): mkh becomes consistent with prop() (edge extrapolation and alpha), and the user already approved the identical change at ~289.
  • (b) Apply only alpha without the edge renormalization (wtsum=alpha), which preserves edge roll-off.
  • (c) Delete the dead block and document that mkh does not renormalize or apply alpha.

The wtsum+=weight in mkht_cubic belongs with this choice. Drop it if (b) or (c) is chosen. Reconstructor results must be revalidated.

  • (b) Leave as is and document the approximation.

Rules for the tests

  • Every test asserts results (the old test_* programs mostly printed or wrote files for manual inspection).
  • No test reads or writes a temporary file. Inputs are generated in memory and file format round trips go through a pipe.
  • Tests that were commented out in the old programs are enabled.
