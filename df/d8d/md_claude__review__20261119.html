Verification of the combined patch

  • Build: a full build of the combined tree with CUDA (sm_120) and OpenMP gives 0 errors.
  • Unit tests: make check passes 23 of 23.
  • End-to-end: I ran scripts/maos_check.sh 5 (29 AO configs, GPU) twice on unpatched 88beaf2da and twice on the patched tree. Every difference between unpatched and patched is within the run-to-run spread of the unpatched build: up to about 9 nm in the MCAO CG/SVD/MVM/CBS cases and under 1 nm elsewhere. One case that looked shifted (FDPCG, +8 nm) was re-run on its own: unpatched 155.4 and 152.6 nm, patched 153.7 and 153.4 nm. So at D=5 m over 100 steps there is no measurable change. This test can't resolve small changes, and many fixes are on paths it doesn't exercise.
  • Not compiled: GTK and Matlab code, because there are no GTK or mex headers on this machine (tools/monitor*, tools/drawdaemon*, tools/scheduler_lws.c, mex/*). The sys/process_apple.c and sys/process_bsd.c changes are also unbuilt here. These were reviewed by reading only.

Your earlier fixes in 88beaf2da that were incomplete

  • lib/mkh.c:
    • Only the cubic loop (~289) was fixed, and it never ran, because wtsum is never accumulated there. The patch adds wtsum+=weight.
    • The bilinear loop (~149) still had bx[count], so bilinear mkh has never renormalized edges or applied alpha. The patch fixes it. This is high impact and is the first item under "Needs your decision" below.
  • sys/sock.c socket_block: F_GETFD was left next to the new F_SETFL. More importantly, now that socket_block(sock,0) really sets O_NONBLOCK, connect_port(..., block=0) would fail with EINPROGRESS, and drawdaemon would treat EAGAIN as a disconnect. The patch removes the non-blocking call in connect_port, whose block argument only controls retries, and makes drawdaemon's socket blocking. That restores the runtime behavior from before 88beaf2da. Without this patch, 88beaf2da breaks scheduler and remote connections.
  • maos/recon_tomo.c: Tomo_iprop_do had the same wfs/wfsr indexing bug (hs and powfs), plus two refactoring regressions: the transpose flag was lost in 7c6d019cf and thetax/thetay in 3756209f2. Together these made it a forward trace instead of the transpose. This only matters for CPU tomography with tomo.square=1 and dbg.tomo_hxw=0.

Security

  • tools/scheduler_http.c read_line_trim / cookie: an empty ~/.aos/htcookie produced the cookie "", and strstr(buf,"") matches every request, which bypassed web authentication. A failed getline also wrote out of bounds. Both are fixed.

Needs your decision

  1. lib/mkh.c bilinear renormalization.
    • (a) Applied: match prop(), with edge renormalization plus alpha.
    • (b) Apply alpha only.
    • (c) Delete the dead block and document that mkh does not renormalize.
    • The cubic wtsum+=weight goes with this choice.
  2. math X(add) with ac==0. The patch makes it scale B by bc, as documented. The alternative is to keep the old no-op and fix servo.c:832 locally instead.
  3. math X(spcell2sp). The patch no longer modifies the const input, and the output is unchanged. The side effect is that muv's A->M keeps its dense block.
  4. math X(minsearch): zero components give a degenerate simplex. Not patched, because the step size depends on the caller.
  5. lib/mkw.c mkw_annular: the normalization cancellation is inexact. Not patched; fixing it would change annular fitting weights.
  6. lib/accphi.c prop_nongrid_rot with cubic: rotation is ignored. The patch only adds a warning; rotation could be implemented instead.
  7. skyc/aster.c multirate: the patch tests SNR at the rate actually assigned (idtrat_fast2). The alternative is to keep the stricter idtrat_fast test.
  8. skyc/genstars.c index: the patch clamps it, so results are bit-identical except for draws that were out of bounds. A uniform floor() draw would change every star field.
  9. maos/powfs.c wfspupmask: unused, and its radius formula always gives d/2. Remove or fix it; not patched.
  10. Behavior choices in tools:
    • ethtest_standalone.c: the F_SETFD line is a no-op. Not patched; recommend deleting it.
    • GTK4 scroll-zoom: the patch also flips the direction to match GTK3. Drop that part if the GTK4 direction was intended.

Noticed but not changed

  • skyc/star.c ~198: dadd(&tmp, 0, ...) inside the wavelength loop overwrites instead of accumulating. It probably should be bc=1.
  • skyc/powfs.c ~97: dinterp1 gets a 2-D xnew, which it rejects.
  • cuda/test/mvmfull_real.cu: sd=cos(theta), which should probably be sin (the same fix was applied in tools/mvm_cpu.c).
  • pcg.cu cgthres: the stopping test is dead unless PRINT_RES is set.
  • sys: zfrewind doesn't reset the zstd decoder; async_init is unsafe for gz/zstd; lock_file_version leaks its fd; udp_recv doesn't bounds-check the packet index.

Needs decision

**#28 socket_block / non-blocking sockets.** Once socket_block works correctly (88beaf2da plus the F_GETFL fix), every socket_block(sock,0) call really makes the socket non-blocking. The code was never written for that: connect_port does a plain connect() and the callers use stread/stwrite with SO_RCVTIMEO.

  • Option A (applied, recommended): keep socket_block correct, remove the socket_block(sock,0) call in connect_port (block only controls retries, as its doc already says), and change drawdaemon_io.c to socket_block(sock,1). Runtime behavior is the same as before 88beaf2da.
  • Option B: keep non-blocking connect in connect_port by adding EINPROGRESS + select()/poll() handling, then switch back to blocking before returning. This is more code and more behavior change.
  • Option C: revert 88beaf2da's sock.c hunk. This is not recommended, because the function would stay wrong.

If the orchestrator does not want this group's patch to touch tools/, the one-line drawdaemon_io.c change must still go into the tools patch. Otherwise drawdaemon will see EAGAIN as a disconnect.

**#20/#21 mkh renormalization (high impact).** Since 2014 (78d14e894), the bilinear mkht renormalization loop has scaled bx[count], an unused slot, so it had no effect. Since 3ed706212, alpha has been applied only through that loop, so bilinear mkh matrices also ignore alpha. In practice alpha is cos(theta*dratio+aoi), which is 1 unless dratio/aoi are set. The fix changes HXW, HA, HXF, the NCPA HA, the pywfs si, and the mkdtf si at edge points where some interpolation neighbors are missing: they get renormalized to sum to alpha, the same as prop(). Options:

  • (a) Keep the patch (recommended): mkh becomes consistent with prop() (edge extrapolation and alpha), and the user already approved the identical change at ~289.
  • (b) Apply only alpha without the edge renormalization (wtsum=alpha), which preserves edge roll-off.
  • (c) Delete the dead block and document that mkh does not renormalize or apply alpha.

The wtsum+=weight in mkht_cubic belongs with this choice. Drop it if (b) or (c) is chosen. Reconstructor results must be revalidated.

  • (a) Warn only (applied).

**#33 mkw_annular.** Options:

  • (b) Leave as is and document the approximation.

No item is marked NEEDS-DECISION. Two related observations for the maintainer:
