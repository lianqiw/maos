sys_mex bug hunt (base e6403afd3)

# file:function status bug and fix impact
1 sys/misc.c:islink (and mex/io.c:islink copy) FIX Used stat(), which follows links, so S_ISLNK was never true and islink() always returned 0. As a result, procfn() (bin.c) never removed an existing symlink before a write, and zfopen("w") truncated and overwrote the link's target file, which is what the code tries to prevent. Now uses lstat(). normal
2 sys/process_linux.c:get_usage_running NEEDS-DECISION (applied) The comment says "Only count 1 thread of MATLAB", but the test was strcmp(exename,"(MATLAB)"), which is true for maos/skyc. So every other maos/skyc process counted as 1 running thread however many threads it ran, and MATLAB was the one enumerated per thread. This feeds get_cpu_avail() in the scheduler (process_queue) and wait_cpu(), so the CPUs used by other running maos jobs were under-counted. Changed to !strcmp. This changes scheduler admission (it is more conservative), not simulation results. normal
3 sys/misc.c:parse_argopt (M_DBL array) FIX (*tmp)[n-1]=(int)val truncated each double array option to an integer. Fixed. No current option uses M_DBL with valtype 2. low
4 sys/misc.c:parse_argopt (array options) FIX With valtype==2 and no value following (for example maos ... -g as the last argument), strtol(NULL,...) dereferenced NULL and segfaulted. It now calls error("Option -g requires a value"). low
5 sys/readstr.c:readstr_numarr (transpose) FIX When len>0 and the user gave more values than len with ' (for example [1 2 3;4 5 6]' for a 4-element key), *ret holds only len values but DO_TRANS read count values: a heap over-read. It now errors, as in the count>len case without transpose (which warns and truncates). low
6 sys/readstr.c:trim_string FIX isspace(end[-1]) was evaluated before start<end. For an empty string (start==end) this read 1 byte before the buffer. The tests are now in the other order. low
7 sys/scheduler_client.c:init_hosts FIX fscanf(fp,"s ",line) into char line[64]: a long name=fqdn:port line in ~/.aos/hosts overflowed the stack. Now uses %63s. normal
8 sys/scheduler_client.c:print_backtrace_symbol FIX The reply len was only checked against >=PATH_MAX. A negative len became a huge size_t in stread, and len==0 left line uninitialized before strlen/dbg. Added len<=0. low
9 sys/daemonize.c:redirect FIX fplog=fopen(...) was not checked, so setbuf(NULL) and fileno(NULL) crashed when the cwd (output dir) is not writable. It now warns and returns. low
10 sys/process.c:init_process FIX fclose(fp) ran when fopen("/proc/meminfo") failed. Now guarded. low
11 sys/process_linux.c:get_job_progname FIX readlink(..., PATH_MAX) followed by path[nprog]='\0' writes one byte past the buffer when the path fills it. Now reads PATH_MAX-1. low
12 sys/process_linux.c:get_job_mem / get_job_launchtime FIX On a failed fscanf, get_job_mem returned an uninitialized mem*pagesize. get_job_launchtime only tested nread<0, so with 0 matches it used an uninitialized starttime0. Now mem is set to 0 and the check is nread!=1. low
13 sys/bin.c:mmap_open FIX When opening a file for reading failed (fd==-1, rw==0), it returned NULL without freeing fn2. low
14 mex/interface.h:d2l / l2d / mx2l FIX mx2d() returns NULL for an empty array or a scalar 0, and d2l() then dereferenced NULL. mx2kalman calls mx2l on dtrat_wfs/dtrats from mxGetField, which is NULL or empty when the field is empty (kalman2mx stores NULL as an empty field). d2l/l2d now return NULL for NULL. normal
15 mex/interface.h:mx2dsp / mx2csp FIX mxIsDouble(A) ran before the A NULL check (the same pattern already fixed in mx2d/mx2c). Now returns NULL first. low
16 mex/io.c:procfn FIX fn2 leaked on each "not found" return, and when remove() of a link failed. low
17 sys/bin.c:zfwrite/zfread (FITS, fcomplex) REPORT-ONLY / NEEDS-DECISION Byte swapping uses the element size. For fcomplex (zmat, size 8), swap_array swaps 8 bytes as one unit, which also exchanges re and im. FITS files written by maos for zmat therefore hold [im,re] per element as external readers (astropy) see them. maos still round-trips because zfread makes the same swap. A fix must change the write side (writearr/async) and the read side (math/readvec, outside this area) together, for example by passing size/2 and 2*n for M_ZMP. low (FITS output of single-precision complex only)
18 sys/bin.c:zfread (FITS, size==1) REPORT-ONLY zfwrite pads FITS data to 2880 bytes for every element size, but zfread consumes the padding only when size>1, because read_fits_header reads 80-byte header lines with size 1. An M_INT8 array (M_STR) in a FITS file is therefore followed by unread padding, and the next HDU fails with "Invalid frame data type". The fix needs a separate data-read path, so it was not changed. low
19 sys/bin.c:async_init/async_write on FITS REPORT-ONLY The async (hole-punch) writer does not handle FITS. zfwrite(&zero,1,1) on a FITS fp writes a whole 2880-byte block at the wrong place, and pwrite writes data without byte swapping or block padding. This is reached only when a writedata(fp,A,-1) stream file is named .fits. A guard (return NULL from async_init if fp->isfits) would also need the matbin caller to fall back to a synchronous write. low
20 sys/bin.c:zfwrite (FITS) / mex/io.c:zfwrite,writedata REPORT-ONLY int length=size*nmemb (and mex int ntot) overflows for arrays of 2 GB or more. low

3 math/matmath.c:X(interp1linear), X(interp1log) NEEDS-DECISION (patch applied) This is the "noticed but not changed" item. So a point at (rx,0) got full val, and points out to sqrt(2)*rx were partially included: the ellipse was about 1.41x too large.
