Build with a C++ compiler (CC=g++), 2026-11-19

Commit: "Fix building with a C++ compiler (CC=g++)".

configure.ac

  • autoconf >= 2.70 dropped the #ifdef __cplusplus extern "C" guard from the prototype in the AC_CHECK_LIB/AC_LINK_IFELSE test program. With CC=g++ conftest.c is compiled as C++, the symbol is name mangled, and every library check failed. m4_define([AC_LANG_CALL(C)], ...) restores the guard.

sys/thread.h

  • The omp_* runtime functions declared locally (to avoid including omp.h) are now declared inside extern "C", which fixes link errors in C++.

sys/common.h: ADDR()

  • &(propdata_t){...} takes the address of a compound literal. In C++ that is a temporary (rvalue) and taking its address is an error without -fpermissive. Added
    #ifdef __cplusplus
    extern "C++"{ template<typename T> static inline T* addr_of(T&& x){ return &x; } }
    #define ADDR(...) addr_of(__VA_ARGS__)
    #else
    #define ADDR(...) (&(__VA_ARGS__))
    #endif
    The temporary lives to the end of the full expression, which covers every use (passing to a function).
  • All 63 uses of &(propdata_t){...} were changed to ADDR((propdata_t){...}) in lib/mkdtf.c, lib/pywfs.c, lib/turbulence.c, lib/zernike.c, maos/aper.c, moao.c, perfevl.c, powfs.c, recon_fit.c, recon_geom.c, recon_setup.c, recon_tomo.c, recon_utils.c, save.c, surf.c, utils.c, wfsgrad.c, skyc/powfs.c and tools/psfiris.c.

test/test_accphi.c

  • Designated initializers were not in declaration order, which C++ rejects.
