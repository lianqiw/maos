monitor: GTK4 deprecated API replacement, 2026-11-19

Commit: "monitor: replace GTK4-deprecated APIs". Files: tools/monitor.c, tools/monitor.h, tools/monitor_gui.c, tools/mygtk.h.

Job list (tools/monitor_gui.c)

  • With GTK >= 4.10 (USE_COLUMN_VIEW, defined in mygtk.h) the job list uses a GListStore of MonJob GObjects shown by a GtkColumnView, wrapped in GtkSortListModel, GtkFilterListModel (per-host page filter) and GtkMultiSelection. This replaces the deprecated GtkListStore + GtkTreeView + GtkTreeModelFilter + GtkCellRenderer code.
  • Columns (date, host, PID, path, status, error, progress, timing, action icon) are built from GtkSignalListItemFactory setup/bind callbacks.
  • Selection, the context menu actions (kill, remove, copy path, plot, etc.) and the clickable action icon work on the selection model.
  • GTK3 and GTK4 < 4.10 keep the old GtkTreeView code. The row content and the per-job action logic are shared by both paths: list_set() fills a row, handle_job() performs an action, job_icon_clicked() handles the icon.
  • tools/monitor.h: proc_t::row is now a job_row_t*, which is a MonJob* with the column view and a GtkTreeRowReference* otherwise.

Dialogs (tools/monitor.c)

  • With GTK >= 4.10 (USE_ALERT_DIALOG) the "Kill all jobs" confirmation uses GtkAlertDialog with Cancel as default and cancel button, replacing the deprecated GtkMessageDialog/gtk_dialog_run.

Bugs fixed on the way

  • Closing the "Kill all jobs" dialog with Escape or the window close button returned GTK_RESPONSE_DELETE_EVENT (nonzero), which the handler treated as "yes" and killed all jobs. Only response 1 now kills.
  • The GtkTreeRowReference of a removed job was never freed.
  • GdkPixbuf values read with gtk_tree_model_get were not unreferenced.
